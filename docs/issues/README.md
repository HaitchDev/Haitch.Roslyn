# Issues

Rules that apply to every issue:

- All code work goes through the Rider MCP tools (`mcp__rider__*`): read, create, edit, build, test, reformat.
- TDD: write the named tests first, run them in Rider and see them fail for the right reason, then write the minimum code to pass, then refactor with tests green.
- Done means: Rider builds the solution with zero warnings (warnings are errors), the whole test suite passes in Rider, and every touched `.cs` file is reformatted in Rider.
- Every shipped type in `src/Haitch.Roslyn` is `internal` (source-only package; public types collide in consumers).
- Every shipped `.cs` file starts with `// <auto-generated/>` then `#nullable enable`, so consumer analyzers and nullable settings do not produce warnings in our code.
- Consumers need C# 14 or later (Polyfill 11.4.0's sources use C# 14 extension blocks); shipped code may use C# 14 features.
- Run tests with `dotnet test` (or `dotnet run --project tests/Haitch.Roslyn.Tests`) from the repo root through `mcp__rider__execute_terminal_command`.
- `.editorconfig` (copied from Haitch.Unions) is the style source: 4-space indentation for `.cs`, `.csproj` and `.props`, 2-space for `.json`.
- `System.HashCode` does not exist on `netstandard2.0` and Polyfill does not provide it; combine hashes manually (`unchecked`, `* 31`) as `EquatableArray` does.
- Never run `git stash`, `git checkout`, `git reset`, `git clean` or anything else that rewrites the working tree: other workers' uncommitted changes live there. Show a failing test by temporarily editing your own files.
- Models and anything that flows through an incremental pipeline hold no `ISymbol`, `SyntaxNode`, `Location`, `Diagnostic` or `Compilation`; only strings, enums, primitives, `EquatableArray<T>` and other value-equal models.
- No new package dependencies beyond those an issue names.
