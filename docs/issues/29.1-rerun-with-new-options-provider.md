# 29.1 AssertCacheable reruns with a new options provider

## Goal
Every `AssertCacheable` rerun gives the driver a new, equal `HarnessAnalyzerConfigOptionsProvider`, so a generator that holds an options provider in a tracked step fails the assertion.

## Touches
- `src/Haitch.Roslyn.Testing/GeneratorHarness.cs`
- `src/Haitch.Roslyn.Testing/HarnessAnalyzerConfigOptions.cs` (only if a factory or copy helper is needed)
- One new test file beside the existing `AssertCacheable` tests (name it in the report)

## Acceptance
`.claude/check.sh` exits 0, including tests where:
- a test generator whose tracked step outputs `context.AnalyzerConfigOptionsProvider` as is (`Select((p, _) => p)`) fails `AssertCacheable` with a `GeneratorTestException` naming that step;
- a generator built on `ForBuildProperty` passes with global options set;
- a generator built on `ForAdditionalFiles` passes with global options set;
- the provider instance seen on each rerun differs from the first run's (captured by a test generator).

## Constraints
- Use `GeneratorDriver.WithUpdatedAnalyzerConfigOptions` before every rerun (unrelated-edit, strict and any other rerun paths), with a provider built from the same `GlobalOptions`/`PerFileOptions`.
- No option to keep the old instance; this is the only behaviour.
- Update `AssertCacheable`'s XML doc to say reruns use a new, equal options provider.
- TDD: behavioural red first, meaning the reference-holding generator passes before the change; show it in the report. Edit only with Rider MCP tools.

## Out of scope
- Migrating `BuildPropertyTests`, `AdditionalFileTests` or `TextConstantsGeneratorTests` (slice 31).
- Changes to additional-text types (slice 30).
