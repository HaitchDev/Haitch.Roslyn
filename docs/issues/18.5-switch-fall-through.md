# 18.5 Switch fall-through

## Goal
`BodyScope` gains `Return(string? expression = null)`, `Throw(string? expression = null)` and `GotoCase(string label)` (`Break`/`Continue` exist from 17.7), and a switch section that doesn't end in a jump throws `InvalidOperationException` when the next section opens, or, as the last section, makes the writer's `ToString()`/`ToSourceText()` throw.

## Touches
- `src/Haitch.Roslyn/Writing/Scopes/BodyScope.cs`
- `src/Haitch.Roslyn/Writing/Scopes/SwitchScope.cs`
- `tests/Haitch.Roslyn.Tests/Writing/Scopes/StatementScopeTests.cs`
- `tests/Haitch.Roslyn.Tests/Writing/Scopes/ScopeGuardTests.cs`

## Acceptance
`dotnet test` from the repo root passes, including tests for the exact output of each new jump method; a section ending in a jump method or in a raw `Line("break;")`/`Line("return x;")`/`Line("throw ...;")`/`Line("continue;")`/`Line("goto case 1;")` passes; an empty section or one ending in another statement throws on the next `Case`/`Default`, and as the last section makes `ToString()` throw while the switch's dispose doesn't; a section whose last statement is a nested block is treated as not ending in a jump (documented).

## Constraints
- The section body records whether its last write was a jump: set by `Break`/`Continue`/the new jump methods, or by a `Line` whose first token is `break`, `return`, `throw`, `continue` or `goto`; cleared by any other write.
- `Dispose` never throws (round rule in 18.1); use the writer's `RecordError` from 18.4.
- Existing switch tests keep passing unchanged.
