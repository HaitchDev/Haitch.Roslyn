# 12.3 Attributes in the typed scoped writer

## Goal
`Attribute(AttributeModel)` on `FileScope`, `NamespaceScope` and `TypeScope` writes the attribute line directly above the next type or member that scope writes.

## Touches
- `src/Haitch.Roslyn/Writing/Scopes/FileScope.cs`
- `src/Haitch.Roslyn/Writing/Scopes/NamespaceScope.cs`
- `src/Haitch.Roslyn/Writing/Scopes/TypeScope.cs`
- `tests/Haitch.Roslyn.Tests/Writing/Scopes/AttributeScopeTests.cs` (new)

## Acceptance
`dotnet test` from the repo root passes the full suite, including new `AttributeScopeTests` that assert the full output string for: two attributes on a type in a namespace, an attribute on each of `Method`, `Field`, `AutoProperty`, `Property` and a nested `Type` with blank lines between siblings but none between an attribute and its member, and an attribute on the first member of a type; plus a test that compiles the generated file (with the user's partial declaration) and asserts zero errors.

## Constraints
- `Attribute` returns its own scope for chaining and writes through 12.1's `RenderAttribute`. It writes the separating blank line itself when one is due, then suppresses the blank line the following type or member would add; the flag lives in each scope's shared `State` class.
- A rejected member (for example an abstract method passed to `Method`) still throws before writing; document that an attribute already written stays in the output.
- An attribute left with nothing after it is a caller error (CS1519 / CS1022); document it alongside the existing accepted limitations on `FileScope`; do not throw from `Dispose`.
- Output of scopes that never call `Attribute` stays byte-identical (the existing scope tests pass unchanged).
- TDD: show the first test failing (CS1061) before the change.
- Edit only with Rider MCP tools; never write files via Bash.

## Out of scope
- Attributes on accessors, parameters or return values; attributes inside `BodyScope` (local functions).
- Writing a model's own `Attributes` automatically.
