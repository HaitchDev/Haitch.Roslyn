# 6.6 Harness checks errors after generation

## Goal
`GeneratorHarness.Run` accepts input sources that only compile once the generator's output, including post-initialization output, is added.

## Touches
- `src/Haitch.Roslyn.Testing/GeneratorHarness.cs`
- `tests/Haitch.Roslyn.Tests/Testing/GeneratorHarnessTests.cs`
- `tests/Haitch.Roslyn.Tests/Sample/SampleGenerator.cs` (use `AddMarkerAttribute`)
- `tests/Haitch.Roslyn.Tests/Sample/SampleGeneratorTests.cs` (drop the hand-declared marker from the inputs)

## Acceptance
`dotnet test` from the repo root passes the full suite, including a new harness test whose input uses an attribute that the generator emits through `RegisterPostInitializationOutput` and that runs without throwing, and the sample tests with the sample generator emitting its marker through `AddMarkerAttribute`.

## Constraints
- Throw only on errors in the output compilation, after generation. Keep the two headings: errors located in input trees go under "Input source errors" and errors in generated trees under "Generated output errors".
- An input error that generation doesn't resolve, such as a plain typo, still throws under "Input source errors". The existing tests for this keep passing.
- `AssertCacheable` behaviour is unchanged.
- TDD: show the new harness test failing with CS0246 before the fix.
