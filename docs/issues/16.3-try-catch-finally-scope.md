# 16.3 Try/catch/finally statement scopes

## Goal
`BodyScope.Try()` returns a `TryScope` whose `Catch` and `Finally` close the open block and open the next, producing a compiling `try` statement.

## Touches
- `src/Haitch.Roslyn/Writing/Scopes/BodyScope.cs`
- `src/Haitch.Roslyn/Writing/Scopes/TryScope.cs` (new `ref struct`)
- `tests/Haitch.Roslyn.Tests/Writing/Scopes/StatementScopeTests.cs`

## Acceptance
`dotnet test` from the repo root passes the full suite, including new tests asserting the full output of `try`/`catch`, `try`/`finally`, `try`/`catch (global::System.IO.IOException ex) when (ex.HResult != 0)`/`catch`/`finally`, a test compiling each with zero errors, a `ScopeCompileCheck` test that `Finally()` followed by `Catch` does not compile (exact id), and `InvalidOperationException` when `Catch` follows a general `catch`.

## Constraints
- `Catch(string? type = null, string? identifier = null, string? filter = null)`: no type writes a general `catch`; an identifier without a type, or a blank given value, throws `ArgumentException` before writing. `Finally()` returns `BodyScope`.
- `TryScope` exposes `Line` and `Block` for the try body; chained-close state is shared as in 16.1.
- A `try` with neither `catch` nor `finally` is a caller error (CS1524): document it with the other accepted limitations; do not throw from `Dispose`.
- Existing output stays byte-identical.
