# 35.1 The writer rejects non-ordinary method kinds

## Goal
`WriteMethodSignature`, `RenderMethodHeader` and `TypeScope.Method` throw an `ArgumentException` naming the `MethodKind` when given a `MethodModel` whose kind is not `Ordinary` or `ExplicitInterfaceImplementation`.

## Touches
- `src/Haitch.Roslyn/Writing/SourceWriterExtensions.cs`
- `src/Haitch.Roslyn/Writing/Scopes/TypeScope.cs` (only if `Method` does not already go through the guarded path)
- `tests/Haitch.Roslyn.Tests/Writing/MethodKindRejectionTests.cs` (exists, failing)

## Acceptance
`.claude/check.sh` exits 0, including every case in `MethodKindRejectionTests`.

## Constraints
- The existing probe test is the red; run it first and include its failure in the report.
- Tighten the probe: it must assert the throw (`ArgumentException`, message contains the kind name), not accept unmangled output as an alternative. Cover constructor, static constructor, destructor, operator and conversion through both `WriteMethodSignature` and `TypeScope.Method`.
- Add one passing case each for an ordinary method and an explicit interface implementation, so the guard does not over-reject.
- The check lives in one place that both entry points share. Document the exception in the XML docs of the public entry points.
- A worker owns every failure in the full suite. Edit only with Rider MCP tools.

## Out of scope
- Writing constructors, operators or destructors.
- Changing `MethodModel.From` or `TypeModel` discovery.
