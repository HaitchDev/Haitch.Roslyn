# 35.2 Partial method implementations keep partial

## Goal
`MethodModel` has `IsPartial` (true for both the definition and implementation parts of a partial method), and the writer emits `partial` whenever `IsPartial` is true, so a written implementation part compiles next to its definition.

## Touches
- `src/Haitch.Roslyn/Models/MethodModel.cs`
- `src/Haitch.Roslyn/Writing/SourceWriterExtensions.cs`
- `tests/Haitch.Roslyn.Tests/Writing/PartialMethodWriteTests.cs` (exists, failing)
- Existing tests or callers the compiler flags when `MethodModel`'s shape changes (list them in the report).

## Acceptance
`.claude/check.sh` exits 0, including every test in `PartialMethodWriteTests`.

## Constraints
- The existing probe tests are the red; run them first and include their failure in the report.
- Follow how `PropertyModel.IsPartial` is declared, computed and documented. `IsPartial` is part of value equality.
- Keep `IsPartialDefinition`; it still distinguishes the two parts.
- Tests cover: implementation part of `partial void M()` and of `public partial int M()` (both keep `partial`, output compiles next to the definition with no errors or warnings via `result.Compilation.GetDiagnostics()` or equivalent); the definition part (unchanged output); a non-partial method (`IsPartial = false`, unchanged output).
- `src/` compiles against Roslyn 4.12; use no newer `IMethodSymbol` API.
- 35.1 may land first in the same file; do not undo its guard.
- A worker owns every failure in the full suite. Edit only with Rider MCP tools.

## Out of scope
- Partial constructors or any other new member kind.
- Changing which methods `TypeModel` collects.
