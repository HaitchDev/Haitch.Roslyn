# 7.2 One item per type in ForTypesWithAttribute

## Goal
`ForTypesWithAttribute` yields one item per marked type, carrying the first marked declaration's `SyntaxInfo` with attributes from every part.

## Touches
- `src/Haitch.Roslyn/Generators/SyntaxValueProviderExtensions.cs`
- `tests/Haitch.Roslyn.Tests/Generators/SyntaxValueProviderExtensionsTests.cs`

## Acceptance
`dotnet test` from the repo root passes, including `SyntaxValueProviderExtensionsTests`: `Should_return_one_item_per_marked_partial_declaration` is replaced by a test that a type marked on two parts in two files yields one item with both attributes, a type marked on one of two parts yields one item whose `SyntaxInfo` is that part's, and the harness cacheability check still passes.

## Out of scope
- `Collect()` or any whole-compilation step (spec forbids it).
- An opt-out flag for the old per-declaration behaviour (nothing released, so the default changes).
- Notes: prerequisites: 6.5 (same test file; the cacheability test uses the harness). Without `Collect()`: in the transform, keep the item only when the current node is the first of `symbol.DeclaringSyntaxReferences` (in declaration order) whose declaration carries the attribute; return null otherwise and filter nulls. Attributes come from `context.Attributes` of all parts, i.e. the symbol's attributes matching the metadata name, not only the current node's. "First" must be deterministic across runs: order by syntax tree position in the compilation, then span start. Watch that removing the attribute from the first part moves the item to the next part (add a test).
