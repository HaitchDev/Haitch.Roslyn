# 30.2 UnreadableAdditionalText

## Goal
The testing package ships `UnreadableAdditionalText(path)`, whose `GetText` returns null, and a harness test uses it to assert the diagnostic a generator reports for an unreadable file.

## Touches
- `src/Haitch.Roslyn.Testing/UnreadableAdditionalText.cs` (new)
- `tests/Haitch.Roslyn.Tests/Testing/UnreadableAdditionalTextTests.cs` (new)

## Acceptance
`.claude/check.sh` exits 0, including tests where:
- `new UnreadableAdditionalText("x.txt")` has `Path == "x.txt"` and `GetText()` returns null;
- a test generator built on `ForAdditionalFiles` reports the `Result` failure as a diagnostic, and the harness test asserts it with `AssertDiagnostic` (id and message substring containing the path), with `AdditionalTexts` mixing a `HarnessAdditionalText` and an `UnreadableAdditionalText`;
- the readable file still produces its output in the same run.

## Constraints
- A public sealed class with an XML doc. Follow the testing package's existing style and namespace.
- TDD: behavioural red against a stub whose `GetText` returns empty text, shown in the report. Edit only with Rider MCP tools.

## Out of scope
- Migrating `AdditionalFileTests` or `TextConstantsGeneratorTests` (slice 31).
