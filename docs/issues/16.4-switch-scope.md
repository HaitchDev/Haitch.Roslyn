# 16.4 Switch statement scope

## Goal
`BodyScope.Switch(expression)` returns a `SwitchScope` whose `Case(label)` and `Default()` each open a braced case section, producing a compiling `switch` statement.

## Touches
- `src/Haitch.Roslyn/Writing/Scopes/BodyScope.cs`
- `src/Haitch.Roslyn/Writing/Scopes/SwitchScope.cs` (new `ref struct`)
- `tests/Haitch.Roslyn.Tests/Writing/Scopes/StatementScopeTests.cs`

## Acceptance
`dotnet test` from the repo root passes the full suite, including new tests asserting the full output of a switch with two constant cases, a multi-label case (`Case("1", "2")`), a pattern case `Case("int i when i > 0")` and `Default()`, a test compiling it with zero errors, a `ScopeCompileCheck` test that `Line` directly on a `SwitchScope` does not compile (CS1061), and `InvalidOperationException` on a second `Default()`.

## Constraints
- `Case(params string[] labels)` writes one `case label:` line per label, then opens a braced block; it returns `BodyScope`. `Default()` writes `default:` and does the same. At least one non-blank label, checked before writing.
- The caller writes `break;`/`return`; fall-through (CS0163) is documented as a caller error.
- Existing output stays byte-identical.
