# 10.2 Type scope

## Goal
`Type(TypeModel)` on a file, namespace or type scope opens a disposable type scope that renders the partial declaration through the existing `SourceWriterExtensions` rendering.

## Touches
- `src/Haitch.Roslyn/Writing/Scopes/TypeScope.cs` (new)
- `src/Haitch.Roslyn/Writing/Scopes/FileScope.cs`
- `src/Haitch.Roslyn/Writing/Scopes/NamespaceScope.cs`
- `src/Haitch.Roslyn/Writing/SourceWriterExtensions.cs` (make the single-declaration line helper `internal`; no behaviour change)
- `tests/Haitch.Roslyn.Tests/Writing/Scopes/TypeScopeTests.cs` (new)

## Acceptance
`dotnet test` from the repo root passes, including `TypeScopeTests`: a namespaced nested generic type matches `WriteTypeDeclaration`'s output byte for byte; a `Type` opened inside a `TypeScope` writes only that type's own declaration; `ScopeCompileCheck` reports CS1061 for `type.Namespace(...)`; existing `SourceWriterExtensionsTests` still pass unchanged.

## Out of scope
- Members (10.3 to 10.5); `Class(name, ...)`-style builders for brand-new, non-partial types (follow-up if wanted).
- Notes: prerequisites: 10.1. `Type` on a file or namespace scope delegates to `WriteTypeDeclaration` (containing types included, file-local throws) and holds its `TypeDeclarationScope`; `Type` on a `TypeScope` renders only the given model's declaration via the now-internal `WriteTypeDeclarationLine`, ignoring `ContainingTypes`, since the parent scope already wrote them. Like the existing renderer this writes partial declarations (no accessibility or `static`); say in the report if that blocks a realistic use.
