# 19.1 Type-parameter variance

## Goal
`TypeParameterModel.Variance` is read from symbols and rendered as `in`/`out`, and `NewTypeModel` rejects variance on anything but an interface.

## Touches
- `src/Haitch.Roslyn/Models/TypeParameterModel.cs`
- `src/Haitch.Roslyn/Writing/SourceWriterExtensions.cs`
- `tests/Haitch.Roslyn.Tests/Models/TypeModelTests.cs`
- `tests/Haitch.Roslyn.Tests/Writing/NewTypeDeclarationTests.cs`

## Acceptance
`dotnet test` from the repo root passes, including tests that `From` reads `in`/`out`/none from `interface IFoo<in T, out U, V>`, that a new interface with variance renders and compiles, that a partial declaration of a variant interface compiles, and that variance on a class/struct/record throws `ArgumentException` with the writer untouched.

## Constraints
- `Variance` is an `init` property using Roslyn's `VarianceKind` or a local enum (no symbol held). Remove the "Variance is not representable yet" remark.
- TDD: behavioural red first. Edit only with Rider MCP tools.

## Out of scope
- Delegates (not a NewType kind).
