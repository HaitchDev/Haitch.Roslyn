# 23.3 Allow input errors

## Goal
With `AllowInputErrors = true`, the harness runs generators against code that does not compile and throws only for errors located in generated trees.

## Touches
- `src/Haitch.Roslyn.Testing/GeneratorHarnessInput.cs`
- `src/Haitch.Roslyn.Testing/GeneratorHarness.cs`
- `src/Haitch.Roslyn.Testing/GeneratorHarnessResult.cs`
- `tests/Haitch.Roslyn.Tests/Testing/GeneratorHarnessInputErrorTests.cs` (new)

## Acceptance
`.claude/check.sh` exits 0, including: input with a syntax error and a missing type runs and exposes both on `result.InputDiagnostics`; a generator emitting broken code still throws `GeneratorTestException` naming the generated file; the default (`false`) still throws on input errors with today's message.

## Constraints
- `InputDiagnostics` holds the input compilation's error diagnostics (empty when none); `Diagnostics` keeps meaning the generator's own.
- An output error counts as generated when its location's syntax tree is a generated tree; errors with no source location count as input errors.
- `AssertCacheable` honours `AllowInputErrors` too.

## Out of scope
- Allowing output errors, warning-level filtering.
