# 24.3 Discovery predicate

## Goal
All four `For…WithAttribute` methods take an optional predicate that further filters syntax nodes after the built-in kind check.

## Touches
- `src/Haitch.Roslyn/Generators/SyntaxValueProviderExtensions.cs`
- `tests/Haitch.Roslyn.Tests/Generators/SyntaxValueProviderExtensionsTests.cs`
- `tests/Haitch.Roslyn.Tests/Generators/MemberDiscoveryTests.cs`

## Acceptance
`.claude/check.sh` exits 0, including: a predicate keeping only `partial` types drops a non-partial attributed type; a predicate keeping only `static` methods; the predicate only ever receives nodes of the method's kind; null keeps today's behaviour.

## Constraints
- Parameter: `Func<SyntaxNode, CancellationToken, bool>? predicate = null`, added last (after `trackingName` / `includeMembers`), so existing calls compile unchanged.
- XML docs say the predicate runs on every edit and must be cheap, syntax-only and capture no state.
- TDD: behavioural red first. Edit only with Rider MCP tools.

## Out of scope
- Semantic (symbol) predicates, new discovery kinds.
