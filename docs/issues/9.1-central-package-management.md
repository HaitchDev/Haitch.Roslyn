# 9.1 Central package management

## Goal
Every package version in the solution comes from a root `Directory.Packages.props`.

## Touches
- `Directory.Packages.props` (new)
- `src/Haitch.Roslyn/Haitch.Roslyn.csproj` (drop `Version` attributes only)
- `src/Haitch.Roslyn.Testing/Haitch.Roslyn.Testing.csproj` (drop `Version` attributes only)
- `tests/Haitch.Roslyn.Tests/Haitch.Roslyn.Tests.csproj` (drop `Version` attributes only)
- `tests/PackageSmoke/Directory.Packages.props` (new, empty `<Project/>`)

## Acceptance
`dotnet build` (0 warnings) then `dotnet test` from the repo root pass, `PackageSmokeTests` included, and `grep -rn 'Version="' --include=*.csproj src tests/Haitch.Roslyn.Tests` prints nothing.

## Out of scope
- Upgrading any version (TUnit 0.90.45, Microsoft.CodeAnalysis.CSharp 4.8.0, Polyfill 11.4.0 stay as they are).
- Package metadata (9.2).
- Notes: prerequisites: 6.1. Match Haitch.Unions' `Directory.Packages.props` layout (`ManagePackageVersionsCentrally` true, one `PackageVersion` per package). The smoke consumer is built out of process from `tests/PackageSmoke/Consumer` and pins a unique per-run `Haitch.Roslyn` version, so it must not inherit central management: the empty `tests/PackageSmoke/Directory.Packages.props` stops the upward lookup, the same way the existing empty `tests/PackageSmoke/Directory.Build.props` does.
