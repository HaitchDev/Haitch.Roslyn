# 23.5 Expected-output assertions

## Goal
`AssertSource(hintName, expected)` and `AssertSourceFile(hintName, path)` compare generated output to inline text or an expected file, with an accept mode that writes the file.

## Touches
- `src/Haitch.Roslyn.Testing/GeneratorHarnessResultAssertions.cs`
- `tests/Haitch.Roslyn.Tests/Testing/SourceAssertionTests.cs` (new)
- `tests/Haitch.Roslyn.Tests/Testing/HarnessDemoTests.cs` (new, slice 23 demo)
- `tests/Haitch.Roslyn.Tests/Testing/Expected/HarnessDemo.g.cs.txt` (new)

## Acceptance
`.claude/check.sh` exits 0, including: inline match and mismatch; file match; mismatch message naming the first differing line with both texts; unknown hint name listing the actual hint names; missing file and `HAITCH_ACCEPT=1` both write the file and fail; CRLF vs LF compares equal; and the demo test (additional file + build property + syntax error input, one asserted diagnostic, one expected file).

## Constraints
- `AssertSourceFile(string hintName, string path, [CallerFilePath] string callerFilePath = "")`: a relative path resolves against the caller's directory, so expected files live next to the test source.
- Expected files use the `.txt` extension so they are not compiled.
- Accept-mode tests write into a temp directory, never into the repo.
- Comparison normalizes line endings only; trailing whitespace counts.
