# 0.7 Polyfill reaches the consumer

## Goal
The package smoke test proves that a `netstandard2.0` project referencing only the Haitch.Roslyn package compiles code that depends on Polyfill-provided types and members.

## Touches
- `tests/PackageSmoke/Consumer/PolyfillUsage.cs` (new)
- `tests/Haitch.Roslyn.Tests/PackageSmokeTests.cs` (only if an assertion is needed that compilation alone cannot give)

## Acceptance
`dotnet test` from the repo root passes the full suite, including `PackageSmokeTests`; temporarily changing Polyfill to `PrivateAssets="all"` in `src/Haitch.Roslyn/Haitch.Roslyn.csproj` makes `PackageSmokeTests` fail with compile errors in `PolyfillUsage.cs`, and reverting makes it pass.

## Out of scope
- Adding a direct Polyfill `PackageReference` to the consumer: Polyfill must arrive only through Haitch.Roslyn.
- Changing `Consumer.csproj`, the src project (except the temporary red check, reverted), or any shipped `.cs` file.
- Notes: the usages must include C# records (a positional `record`, a `record struct`, an `init`-only property, a `with` expression and value equality), which need Polyfill's `IsExternalInit` on `netstandard2.0`.
- Notes: pick usages that do not exist on `netstandard2.0` without Polyfill, verified against the Polyfill 11.4.0 package in `~/.nuget/packages/polyfill/11.4.0`. Cover at least one of each: a compiler-support attribute/type (e.g. `init` or `required` members, `Index`/`Range`), a nullable attribute (e.g. `[NotNullWhen]`), and a polyfilled member (instance extension such as `string.Contains(char)`, or a C# 14 static extension such as `ArgumentNullException.ThrowIfNull`). Do not use `System.HashCode` (Polyfill does not provide it).
