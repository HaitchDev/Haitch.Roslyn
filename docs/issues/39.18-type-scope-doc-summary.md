# 39.18 TypeScope writes a doc summary above the next member

## Goal
`TypeScope.Summary(string text)` buffers `/// <summary>{text}</summary>` for the next member, so it is written after that member's blank separator line and directly above its attributes and header, for every member kind a type scope writes (`Block`, `Method`, `Field`, properties, events, nested types).

## Touches
- `src/Haitch.Roslyn/Writing/Scopes/TypeScope.cs`
- `src/Haitch.Roslyn/Writing/SourceWriter.cs` (only if the pending-member state lives there)
- the `TypeScope` writer test file 39.14/39.15 used

## Acceptance
`.claude/check.sh` exits 0.

## Constraints
- Found by Haitch.Validation 084: its generator writes `/// <summary>…</summary>` above each message method; written via `TypeScope.Line` then `Block`, `BeginMember` puts the blank separator between the comment and the method. Haitch.Roslyn has no doc-comment API today.
- Follow how pending attributes (`TypeScope.Attribute`) are buffered and flushed by `BeginMember`: same lifetime and the same error when the scope is disposed with a pending summary and no member after it. Order above a member: summary, then attributes, then header. A second `Summary` before a member is an error, the same kind of error as other misuse in this writer. Text is written verbatim (no XML escaping; document that the caller escapes).
- TDD, one commit per step, distinct behaviours only: (1) summary goes after the blank separator, directly above the header; (2) summary goes above pending attributes; (3) pending summary with no member reports like a pending attribute does; (4) second summary before a member is an error. Each `test:` red first, minimal `feat:` that never edits test expectations, at least one `refactor:` with the check green.
