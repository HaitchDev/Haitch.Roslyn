# 8.2 End-to-end sample generator

## Goal
A test-project sample generator built on `ForTypesWithAttribute`, `Validate`, `ReportDiagnostics`, `HintName.For` with `SourceWriterExtensions` passes harness tests of its output, its diagnostics, its cacheability.

## Touches
- `tests/Haitch.Roslyn.Tests/Sample/SampleGenerator.cs` (new)
- `tests/Haitch.Roslyn.Tests/Sample/SampleGeneratorTests.cs` (new)

## Acceptance
`dotnet test` from the repo root passes, including `SampleGeneratorTests`: a two-part partial type produces exactly one file under its `HintName.For` name; a non-partial marked type produces the caller's diagnostic and no file; `GeneratorHarness.AssertCacheable` passes for the generator's named steps.

## Out of scope
- Shipping the sample in a package or the smoke consumer.
- Any change under `src/`; if a gap appears, report it instead of fixing it here.
- Notes: prerequisites: 6.4, 7.1, 7.2, 8.1. The generated file is small and real (e.g. a `ToString` override or a `const string TypeName`), written with `WriteAutoGeneratedHeader`, `WriteNamespace` and `WriteTypeDeclaration`, and must compile (the harness enforces it). Descriptors are test-only, with the `#pragma warning disable RS2008` pattern used in `Diagnostics/TestGenerator.cs`. Name tracking steps through `ForTypesWithAttribute`'s and `ReportDiagnostics`'s `trackingName` parameters and pass those names to `AssertCacheable`.
