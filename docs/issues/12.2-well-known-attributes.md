# 12.2 Well-known generated-code attributes

## Goal
`WellKnownAttributes.GeneratedCode(tool, version)` and `WellKnownAttributes.EditorBrowsableNever` return `AttributeModel`s that render through 12.1 as compiling `GeneratedCode` and `EditorBrowsable(Never)` attributes.

## Touches
- `src/Haitch.Roslyn/Models/WellKnownAttributes.cs` (new, `internal static class`)
- `tests/Haitch.Roslyn.Tests/Writing/AttributeRenderingTests.cs`

## Acceptance
`dotnet test` from the repo root passes the full suite, including new tests that assert the exact rendered lines `[global::System.CodeDom.Compiler.GeneratedCodeAttribute("Tool", "1.0.0")]` and `[global::System.ComponentModel.EditorBrowsableAttribute(global::System.ComponentModel.EditorBrowsableState.Never)]`, that each factory result equals the `AttributeModel.From` result for the same attribute written in source, and that a type and a method carrying both compile with zero errors.

## Constraints
- Build models with `TypeRef` and `ConstantValue.ForString`/`ForEnum`; no symbols. `EditorBrowsableNever` is a cached `static readonly` instance.
- The equality test is the guard that the hand-built `TypeRef`s (nullable annotation, special type, type kind) match what Roslyn produces; fix the factory, not the test, if it fails.
- New shipped file starts with `// <auto-generated/>` then `#nullable enable`; the type is `internal`.
- TDD: show the equality test failing before the factory exists.
- Edit only with Rider MCP tools; never write files via Bash.

## Out of scope
- Other attributes (`ExcludeFromCodeCoverage`, `DebuggerNonUserCode`, `CompilerGenerated`); add later on demand.
- Using them in the sample generator.
- Notes: prerequisite 12.1.
