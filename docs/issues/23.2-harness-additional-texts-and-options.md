# 23.2 Harness additional texts and analyzer-config options

## Goal
Additional texts, global options and per-file options on `GeneratorHarnessInput` reach the generator driver.

## Touches
- `src/Haitch.Roslyn.Testing/GeneratorHarnessInput.cs`
- `src/Haitch.Roslyn.Testing/GeneratorHarness.cs`
- `src/Haitch.Roslyn.Testing/HarnessAnalyzerConfigOptions.cs` (new, internal)
- `tests/Haitch.Roslyn.Tests/Testing/GeneratorHarnessOptionsTests.cs` (new)

## Acceptance
`.claude/check.sh` exits 0, including tests where a test generator reads an additional text's path and content, a global `build_property.RootNamespace`, and a per-file `build_metadata.AdditionalFiles.Kind` for one additional text, and emits them; and an `AssertCacheable` run with additional texts and options passes.

## Constraints
- `AdditionalTexts` is `IReadOnlyList<HarnessAdditionalText>`, where `HarnessAdditionalText(string Path, string Text)` is a public record in `GeneratorHarnessInput.cs`.
- `GlobalOptions` is `IReadOnlyDictionary<string, string>`; `PerFileOptions` is `IReadOnlyDictionary<string, IReadOnlyDictionary<string, string>>` keyed by path, applying to source trees (paths as the harness names them, documented) and additional texts.
- Keys are passed through verbatim (callers write `build_property.X`); lookups are case-insensitive like the compiler's.
- `AssertCacheable` passes the same texts and options on every run, so a rerun with no edits stays cached.
- TDD: behavioural red first. Edit only with Rider MCP tools.

## Out of scope
- Editing additional texts between cacheability runs, library-side option helpers (26.x).
