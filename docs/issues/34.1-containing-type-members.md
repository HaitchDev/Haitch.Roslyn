# 34.1 Member discovery can include containing-type members

## Goal
`ForFieldsWithAttribute`, `ForPropertiesWithAttribute` and `ForMethodsWithAttribute` take `bool includeContainingTypeMembers = false`; when true, each result's `ContainingType` has its fields, properties, methods and events filled exactly as `ForTypesWithAttribute(..., includeMembers: true)` fills them.

## Touches
- `src/Haitch.Roslyn/Generators/SyntaxValueProviderExtensions.cs`
- The existing member-discovery test file(s) in `tests/Haitch.Roslyn.Tests/` (name them in the report), or one new test file there.

## Acceptance
`.claude/check.sh` exits 0, including the new tests.

## Constraints
- Place the parameter in the same position `includeMembers` has in `ForTypesWithAttribute`, and thread it into the private `ForMembersWithAttribute` so `ContainingType` is built with `TypeModel.From(definition.ContainingType, includeContainingTypeMembers, ct)`.
- Tests, per discovery method: default leaves `ContainingType` members empty; `true` fills them (assert on a sibling member that has no attribute). One `AssertCacheable` test with `true` shows a trivia edit leaves the step cached and adding a sibling member makes it rerun.
- Mutation check: pass `false` instead of the parameter in the `ForMembersWithAttribute` call and show the `true` tests fail.
- XML docs on each method say the option ties the step's equality to every member edit of the containing type, like the `includeMembers` remark. Fix that existing remark to list events as well.
- A worker owns every failure in the full suite. Edit only with Rider MCP tools.

## Out of scope
- The Notify sample (34.2).
- An events variant of member discovery.
