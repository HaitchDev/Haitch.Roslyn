# 38.1 ForTypesWithAttribute carries an extra transform

## Goal
A `ForTypesWithAttribute` overload takes an extra transform whose value-equal result rides along in each item, so a generator extracts its own model (e.g. from a method body) without giving up dedupe and caching.

## Touches
- `src/Haitch.Roslyn/Generators/SyntaxValueProviderExtensions.cs`
- `tests/Haitch.Roslyn.Tests/Generators/SyntaxValueProviderExtensionsTests.cs`

## Acceptance
`.claude/check.sh` exits 0, including the new extra-transform tests in `SyntaxValueProviderExtensionsTests`.

## Constraints
- Signature: `ForTypesWithAttribute<TExtra>(this SyntaxValueProvider provider, string fullyQualifiedMetadataName, string trackingName, Func<GeneratorAttributeSyntaxContext, CancellationToken, TExtra> transform, bool includeMembers = false, Func<SyntaxNode, CancellationToken, bool>? predicate = null) where TExtra : IEquatable<TExtra>`, returning `IncrementalValuesProvider<(TypeModel Type, SyntaxInfo Syntax, EquatableArray<AttributeModel> Attributes, TExtra Extra)>`. Existing calls to the non-generic overload compile and behave unchanged.
- The extra transform runs inside the same `ForAttributeWithMetadataName` transform, only for the declaration that the existing dedupe keeps; a partial type marked on several declarations still yields one item, and the transform is not called for the dropped declarations. Test both.
- Share the existing dedupe/model-building path with the non-generic overload; do not duplicate it.
- Cacheability: with the Haitch.Roslyn.Testing harness, an edit to an unrelated file leaves the step cached, and an edit that changes the extra value recomputes it. Test both.
- XML doc comments on the new overload, in the style of the existing one; the `transform` doc says its result must be value-equal and hold no `ISymbol`, `SyntaxNode`, `Location`, `Diagnostic` or `Compilation`.
- TDD in tiny steps, one hat at a time: each behaviour step starts from a test seen failing for the right reason, then the minimum code to pass; refactors are separate steps with tests green. A later test that passes on first run means the earlier `feat:` overshot; avoid that.
- Commit every step: the failing test alone as `test: ...`, then `feat: ...` only when it turns that test green, and each refactor as its own `refactor: ...`. Lowercase conventional subject only, no body, no trailers. Stage paths explicitly. Commit this issue file first as `docs: add issue 38.1 for types extra transform`.
- Rider MCP is not available to this worker: edit with Edit/Write (not `sed -i`), build and test with the dotnet CLI, format with `dotnet csharpier format` on touched files.
- `src/` compiles against Roslyn 4.12.

## Out of scope
- Extra-transform overloads for the method, property and field providers.
- Any change to `TypeModel`, `SyntaxInfo` or other models.
- `docs/handoff.md` (it has an uncommitted edit that is not ours) and the issue index in `docs/issues/README.md`.
- Tagging; pushing happens only after the check passes, as the last step.
