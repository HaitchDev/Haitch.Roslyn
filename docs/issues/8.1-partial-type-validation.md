# 8.1 Partial type validation

## Goal
`PartialTypeValidation.Validate(TypeModel, SyntaxInfo, PartialTypeDiagnostics)` returns a `Result<TypeModel>` that fails with the caller's descriptors, at the declaration's location, for a non-partial type, a non-partial containing type or a file-local type.

## Touches
- `src/Haitch.Roslyn/Diagnostics/PartialTypeValidation.cs` (new; holds `PartialTypeDiagnostics` and `PartialTypeValidation`)
- `tests/Haitch.Roslyn.Tests/Diagnostics/PartialTypeValidationTests.cs` (new)

## Acceptance
`dotnet test` from the repo root passes, including `PartialTypeValidationTests`: a valid partial type succeeds with the same `TypeModel`; each rule fails with its descriptor id, the type name as message argument and the `SyntaxInfo` location; a type breaking two rules gets both diagnostics.

## Out of scope
- Defining descriptor ids, titles or messages (the caller supplies them).
- Checks beyond the three listed (accessibility, static, generic constraints).
- Notes: prerequisites: none (uses 2.x, 3.4, 3.5). `internal sealed record PartialTypeDiagnostics(DiagnosticDescriptor NotPartial, DiagnosticDescriptor ContainingTypeNotPartial, DiagnosticDescriptor FileLocal)`; it is generator configuration (a `static readonly` field), never a pipeline value. Every failing rule is reported (not first-only), in the order listed. Message argument is the type's name only (`TypeModel.Name`); the containing-type rule uses the same location since `SyntaxInfo` stores one. Uses `TypeModel.IsFileLocal`, `SyntaxInfo.IsPartial`, `SyntaxInfo.AreContainingTypesPartial`, `SyntaxInfo.Location`.
