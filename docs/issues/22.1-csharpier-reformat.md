# 22.1 csharpier tool and whole-repo reformat

## Goal
`dotnet csharpier check .` exits 0 on the repo, with csharpier pinned as a local dotnet tool.

## Touches
- `.config/dotnet-tools.json` (new)
- `.csharpierignore` (new, only if generated or fixture files need excluding)
- Every `*.cs` file csharpier reformats (mechanical changes only; exempt from the five-file rule)

## Acceptance
`dotnet tool restore && dotnet csharpier check . && dotnet test` from the repo root exits 0.

## Constraints
- Red: show `dotnet csharpier check .` failing after the manifest is added and before the reformat.
- Pin the latest stable csharpier 1.x; no other tools or packages.
- The reformat is the only code change: no renames, no hand edits. Run the formatter through the Rider terminal tool, not a Bash write.
- Exact-output tests compare generated text, not test-source layout; if a reformat changes a raw string literal that is compared verbatim, exclude that file in `.csharpierignore` instead of editing it, and name it in the report.

## Out of scope
- `.claude/check.sh`, CI changes, `.editorconfig` style changes.
