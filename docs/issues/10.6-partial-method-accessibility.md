# 10.6 Partial method accessibility

## Goal
Writing the implementation of a user-declared partial method produces a declaration that compiles alongside it, whether or not the user's declaration has an access modifier.

## Touches
- `src/Haitch.Roslyn/Models/MethodModel.cs` (add `HasExplicitAccessibility`)
- `src/Haitch.Roslyn/Writing/SourceWriterExtensions.cs` (skip accessibility when it is implicit)
- `tests/Haitch.Roslyn.Tests/Models/MemberModelTests.cs`
- `tests/Haitch.Roslyn.Tests/Writing/Scopes/MethodScopeTests.cs`

## Acceptance
`dotnet test` from the repo root passes the full suite, including new tests that build a `MethodModel` from `partial void OnX();` and from `public partial int M();`, write the implementation via `TypeScope.Method`, and compile the user declaration plus the output with zero errors.

## Constraints
- `HasExplicitAccessibility` comes from the declaring syntax's modifiers (any of `public`, `private`, `protected`, `internal`, `file` is not an accessibility). It is a plain `bool`; the model still holds no syntax or symbols, and stays value-equal.
- For a method with several declarations (partial definition and implementation), use the definition part (`PartialDefinitionPart ?? symbol`).
- Existing `WriteMethodSignature` output stays byte-identical for methods with explicit accessibility; existing tests pass unchanged.
