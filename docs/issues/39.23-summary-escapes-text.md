# 39.23 TypeScope.Summary writes any text as a well-formed doc comment

## Goal
`TypeScope.Summary(string text)` escapes XML and writes one `///` line per line of `text`, so any string yields a summary that compiles without CS1570 under `GenerateDocumentationFile`.

## Touches
- `src/Haitch.Roslyn/Writing/Scopes/TypeScope.cs`
- `tests/Haitch.Roslyn.Tests/Writing/Scopes/TypeScopeTests.cs` (a split-out `TypeScopeTests.Summary.cs` in the same directory is fine)

## Acceptance
`.claude/check.sh` exits 0.

## Constraints
- Found by Haitch.Validation 329: it passes a user's `message:` template to `Summary` raw; a template holding a newline breaks the generated file (CS0116), and `<` or `&` give CS1570. The current doc says "written verbatim, so the caller escapes XML"; that contract changes: `Summary` escapes, and its doc says so. Haitch.Validation is the only caller and does not pre-escape.
- Escaping: `&` → `&amp;`, `<` → `&lt;`, `>` → `&gt;`. A character XML 1.0 cannot hold (U+0000–U+001F other than tab, U+FFFE, U+FFFF, a lone surrogate) is written as the text `\uXXXX` (four uppercase hex digits).
- Lines: C# line terminators split `text` (CRLF, CR, LF, U+0085, U+2028, U+2029). Single-line text keeps today's exact output `/// <summary>text</summary>`. Multi-line text is written as `/// <summary>`, one `/// line` per line (an empty line is `///`), then `/// </summary>`.
- Tests: (1) `<`, `>`, `&` escaped on one line; (2) LF and CRLF give one `///` line each; (3) U+2028 splits too; (4) a control character becomes `\uXXXX`; (5) one end-to-end row: a type with a summary holding a newline, `<` and `&` compiles with `DocumentationMode.Diagnose` and no diagnostics (read `Compilation.GetDiagnostics()`, warnings included). Existing single-line expectations stay unchanged.
- No allocation per character: scan once (`IndexOfAny`/a loop over the span), append runs to one `StringBuilder`; the plain single-line case allocates only the line it writes.
- Lowercase conventional subject only, no body, no trailers (never Co-Authored-By). Stage paths explicitly with `git commit -- <paths>`. Commit this issue file first as `docs: add issue 39.23 summary escapes text`.

Never run `git stash`, `git checkout`, `git reset` or `git clean` (other uncommitted changes, e.g. `docs/handoff.md`, live in this tree; leave them alone).
