# 20.2 Explicit interface members

## Goal
`PropertyModel` records an explicit interface implementation, and `TypeModel.From(includeMembers: true)` includes explicit method and property implementations, flagged by their `ExplicitInterface`.

## Touches
- `src/Haitch.Roslyn/Models/PropertyModel.cs`
- `src/Haitch.Roslyn/Models/TypeModel.cs`
- `tests/Haitch.Roslyn.Tests/Models/MemberModelTests.cs`
- `tests/Haitch.Roslyn.Tests/Models/TypeModelTests.cs`

## Acceptance
`dotnet test` from the repo root passes, including tests that a type implementing `IDisposable.Dispose` and `IFoo.Bar { get; }` explicitly yields both in `Methods`/`Properties` with `ExplicitInterface` set and the member name unqualified, that ordinary members have it null, and that the sample generator's existing tests still pass.

## Constraints
- `ExplicitInterface` on `PropertyModel` mirrors `MethodModel`'s (`TypeRef?`, plus the interface member name), as `init` properties.
- `RenderAutoProperty` keeps rejecting explicit implementations, now by checking `ExplicitInterface` instead of a dotted name; message updated.

## Out of scope
- Explicit indexers and events.
