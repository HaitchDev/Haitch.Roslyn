# 20.3 Volatile fields and ref properties

## Goal
`FieldModel.IsVolatile` and `PropertyModel.ReturnRefKind` are read from symbols and rendered by the field and property writers, and `AutoProperty` rejects ref-returning models.

## Touches
- `src/Haitch.Roslyn/Models/FieldModel.cs`
- `src/Haitch.Roslyn/Models/PropertyModel.cs`
- `src/Haitch.Roslyn/Writing/SourceWriterExtensions.cs`
- `tests/Haitch.Roslyn.Tests/Models/MemberModelTests.cs`
- `tests/Haitch.Roslyn.Tests/Writing/Scopes/FieldAndPropertyScopeTests.cs`

## Acceptance
`dotnet test` from the repo root passes, including tests that `From` reads `volatile` and `ref`/`ref readonly` returns, that a volatile field renders and compiles, that a ref-returning property written via `PropertyScope` with a getter body renders `ref`/`ref readonly` and compiles, and that `AutoProperty` on a ref-returning model throws `ArgumentException` with the writer untouched.

## Constraints
- `init` properties; `ReturnRefKind` uses the `ReturnRefKind` enum, as `MethodModel` does.
- `TypeScope.Property` rejects a ref-returning model that has a `set` or `init` accessor (CS8147).

## Out of scope
- `required`, `scoped`, fixed-size buffers.
