# 6.2 GeneratorHarness

## Goal
`GeneratorHarness.Run` returns a step-tracked generator run's sources by hint name with its diagnostics, throwing `GeneratorTestException` when the output does not compile.

## Touches
- `src/Haitch.Roslyn.Testing/GeneratorHarness.cs` (new)
- `src/Haitch.Roslyn.Testing/GeneratorHarnessResult.cs` (new)
- `tests/Haitch.Roslyn.Tests/Testing/GeneratorHarnessTests.cs` (new)

## Acceptance
`dotnet test` from the repo root passes, including `GeneratorHarnessTests`: a fixture generator's source is returned under its hint name, a reported diagnostic is returned, and a generator emitting invalid C# makes `Run` throw with the error id, file and line in the message.

## Out of scope
- Rerun or cacheability assertions (6.3), hazard walking (6.4).
- Notes: prerequisites: 6.1. Suggested shape: `GeneratorHarness.Run(IIncrementalGenerator generator, IEnumerable<string> sources, IEnumerable<MetadataReference>? additionalReferences = null, CSharpParseOptions? parseOptions = null)`. References default to the running runtime's `TRUSTED_PLATFORM_ASSEMBLIES` (no Basic.Reference.Assemblies or other new dependency). The driver is created with `GeneratorDriverOptions(IncrementalGeneratorOutputKind.None, trackIncrementalGeneratorSteps: true)`. `GeneratorHarnessResult` exposes `IReadOnlyDictionary<string, string> Sources`, `ImmutableArray<Diagnostic> Diagnostics` (generator-reported), the output `Compilation`, the `GeneratorDriver` after the run and the `GeneratorDriverRunResult`, so 6.3 can rerun. Only error-severity compiler diagnostics of the output compilation throw; generator-reported diagnostics never throw (8.2 relies on that). Default parse options use the newest version Roslyn 4.8 knows (`LanguageVersion.Latest`, i.e. C# 12). Every public member has XML docs (9.2 turns on documentation files).
