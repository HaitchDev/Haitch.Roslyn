# 0.2 Polyfill integration

## Goal
The package builds for `netstandard2.0` with Polyfill, the tests compile the package sources directly as a consumer would, and the packed nuspec declares Polyfill as a dependency.

## Touches
- `src/Haitch.Roslyn/Haitch.Roslyn.csproj`
- `src/Haitch.Roslyn/Types/EquatableArray.cs` (revert the demo `Length` property only, if still present)
- `tests/Haitch.Roslyn.Tests/Haitch.Roslyn.Tests.csproj`
- `tests/Haitch.Roslyn.Tests/PackageSurfaceTests.cs`
- `tests/Haitch.Roslyn.Tests/PolyfillTests.cs` (delete, if still present)

## Acceptance
`dotnet build` of the solution succeeds with zero warnings; `dotnet test` passes the full suite, with `PackageSurfaceTests` shown red when a type under `src` is made public and green after reverting; `dotnet pack` of the src project produces a nuspec listing `Polyfill` and not `Microsoft.CodeAnalysis.CSharp`.

## Out of scope
- The consumer smoke test (0.3).
- Any other new dependency.
- Notes (decided by the human): src targets only `netstandard2.0`; no `InternalsVisibleTo`; the test project has no `ProjectReference` to src and instead compiles `src/Haitch.Roslyn/**/*.cs` (excluding `bin`/`obj`) and references Polyfill directly with `PrivateAssets="all"` at the same version as src. `PackageSurfaceTests` checks the types compiled into the test assembly whose namespace is `Haitch.Roslyn` or starts with `Haitch.Roslyn.` but is not `Haitch.Roslyn.Tests`, and asserts none is public (top-level `IsPublic`, or nested public inside a public type).
