# 6.5 Dogfood the harness

## Goal
This repo's hand-rolled incremental caching tests assert through `GeneratorHarness.AssertCacheable` instead of driving `CSharpGeneratorDriver` themselves.

## Touches
- `tests/Haitch.Roslyn.Tests/Generators/SyntaxValueProviderExtensionsTests.cs`
- `tests/Haitch.Roslyn.Tests/Diagnostics/ResultPipelineExtensionsTests.cs`
- `tests/Haitch.Roslyn.Tests/Diagnostics/TestGenerator.cs` (only if a tracking name must become public to the harness)

## Acceptance
`dotnet test` from the repo root passes with the same test count as before; temporarily making `SyntaxValueProviderExtensions` return a fresh `object` in its tracked step makes the migrated test fail with the harness message.

## Out of scope
- Migrating tests that do not check caching.
- Changing any `src/` behaviour.
- Notes: prerequisites: 6.4. Spec-next.md says "three" tests; the repo has two step-tracking tests covering three reruns: `Should_report_the_value_step_as_cached_or_unchanged_after_an_unrelated_edit_in_another_file` (unrelated edit, then a trivia edit) in `SyntaxValueProviderExtensionsTests`, and `Should_report_the_value_step_as_unchanged_for_an_entry_with_a_trivia_only_edit` in `ResultPipelineExtensionsTests`. Where a test asserts something stronger than the harness (e.g. `Unchanged` rather than `Cached` or `Unchanged`), keep that extra assertion on the returned result rather than weakening it. If the harness cannot express an edit (the unrelated edit in a second file), keep that part hand-rolled and say why in the report.
