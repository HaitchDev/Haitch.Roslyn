# 23.1 GeneratorHarnessInput

## Goal
`GeneratorHarness.Run` and `AssertCacheable` accept a `GeneratorHarnessInput` options object, and the existing overloads delegate to the new ones.

## Touches
- `src/Haitch.Roslyn.Testing/GeneratorHarnessInput.cs` (new)
- `src/Haitch.Roslyn.Testing/GeneratorHarness.cs`
- `tests/Haitch.Roslyn.Tests/Testing/GeneratorHarnessInputTests.cs` (new)

## Acceptance
`.claude/check.sh` exits 0, including tests that run a generator through `Run(generator, input)` and `AssertCacheable(generator, input, steps)` with sources, extra references and custom parse options, and get the same result as the equivalent old overloads.

## Constraints
- `GeneratorHarnessInput` is a public sealed class with `init` properties: `Sources` (required), `AdditionalReferences`, `ParseOptions`. Later issues add `AdditionalTexts`, `GlobalOptions`, `PerFileOptions` and `AllowInputErrors`; design so adding them is additive.
- New overloads: `Run(IIncrementalGenerator, GeneratorHarnessInput)`, `AssertCacheable(IIncrementalGenerator, GeneratorHarnessInput, IEnumerable<string> steps, CacheabilityOptions? options = null)`.
- Every existing public overload keeps its exact signature and behaviour and delegates to the new ones; existing tests are not edited.
- Public members have XML docs.
- TDD: behavioural red first. Edit only with Rider MCP tools.

## Out of scope
- Additional texts, analyzer-config options, input-error tolerance, assertions.
