# 15.2 Migrate hand-rolled reruns to the harness

## Goal
The caching tests from 6.5 and 7.2 assert through `AssertCacheable` with `CacheabilityOptions` and drive no `GeneratorDriver` themselves.

## Touches
- `tests/Haitch.Roslyn.Tests/Generators/SyntaxValueProviderExtensionsTests.cs`
- `tests/Haitch.Roslyn.Tests/Diagnostics/ResultPipelineExtensionsTests.cs`

## Acceptance
`dotnet test` from the repo root passes with the same test count as before, including `Should_report_the_value_step_as_cached_or_unchanged_after_an_unrelated_edit_in_another_file` (now `UnrelatedEditSourceIndex = 2`) and `Should_report_the_value_step_as_unchanged_for_an_entry_with_a_trivia_only_edit` (now `RequireRecomputationAfterTriviaEdit = true`); temporarily making each tracked step return a fresh `object` makes both fail with the harness message (show the output, then revert).

## Constraints
- Do not weaken an assertion. The strict test may drop `OtherWidget` to a single source only because `OtherWidget`'s outputs are `Cached` (another tree), not because they fail; say so in a comment, one line.
- Remove `GetValuesStepReasons` and other helpers only if nothing else uses them.
- Tests that check behaviour across runs rather than caching (`Should_move_the_item_between_parts_across_incremental_runs_on_the_same_driver`) stay hand-rolled.
- Edit only with Rider MCP tools; never write files via Bash.

## Out of scope
- Any `src/` change; if the harness cannot express a case, stop and report.
- Notes: prerequisite 15.1; supersedes the hand-rolled remainder of 6.5 and 7.2.
