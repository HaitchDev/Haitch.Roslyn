# 18.4 Try guards

## Goal
A `TryScope` disposed with neither a catch nor a finally makes the writer's `ToString()`/`ToSourceText()` throw `InvalidOperationException`, and a catch whose exception type text repeats an earlier catch throws immediately.

## Touches
- `src/Haitch.Roslyn/Writing/SourceWriter.cs` (internal `RecordError(string)`; `ToString`/`ToSourceText` throw the first recorded error)
- `src/Haitch.Roslyn/Writing/Scopes/TryScope.cs`
- `tests/Haitch.Roslyn.Tests/Writing/Scopes/ScopeGuardTests.cs`

## Acceptance
`dotnet test` from the repo root passes, including `ScopeGuardTests`: bare `Try()` disposed does not throw but `ToString()` and `ToSourceText()` then do, naming the try; `Catch("IOException")` twice throws; `Catch("IOException", when: ...)` then `Catch("IOException")` does not throw (filters make repeats legal); `Exception`, `System.Exception` and `global::System.Exception` count as the general catch for the existing after-general check.

## Constraints
- `Dispose` never throws (round rule in 18.1); it closes the block, then records the error on the writer.
- Catch types compare by exact trimmed text, except the three spellings of `Exception` above. No type-hierarchy ordering.
- Existing tests that throw `ArgumentException` mid-try and then inspect output may now see the recorded error; adjust only by asserting on the output via a path that doesn't call `ToString()` (or by expecting the recorded error), never by weakening the guard.
