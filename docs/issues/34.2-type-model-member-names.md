# 34.2 TypeModel carries every member name

## Goal
`TypeModel.From(type, includeMembers: true, ct)` fills a new `MemberNames` with the distinct, ordinal-sorted `Name` of every member `type.GetMembers()` returns (nested types, indexers, constructors, operators and compiler-made members included); with `includeMembers: false` it is empty.

## Touches
- `src/Haitch.Roslyn/Models/TypeModel.cs`
- The existing `TypeModel` test file in `tests/Haitch.Roslyn.Tests/` (name it in the report), or one new test file there.
- Callers the compiler flags if `TypeModel`'s constructor shape changes (list them).

## Acceptance
`.claude/check.sh` exits 0, including the new tests.

## Constraints
- `MemberNames` is an `EquatableArray<string>` in value equality, computed like the Notify sample's `NotifyOwner.MemberNames` today (`samples/Haitch.Roslyn.Samples/NotifyGenerator.cs`, `NotifyOwner.From`): `GetMembers().Select(m => m.Name).Distinct().OrderBy(n => n, StringComparer.Ordinal)`.
- The XML doc says why compiler-made members are included: a generated member can clash with them (for example a record's synthesized `ToString`). It also says an explicit interface implementation appears under its qualified name.
- Tests: a type with a nested type, an indexer, a constructor, an operator and an explicit implementation lists the expected names; a record lists its synthesized members; `includeMembers: false` gives an empty array; two models of the same source are equal and adding a nested type makes them unequal.
- Show the tests failing against a stub that leaves `MemberNames` empty.
- Shipped sources are compiled standalone: explicit usings only. Roslyn 4.12 floor.
- Do not change the Notify sample. A worker owns every failure in the full suite. Edit only with Rider MCP tools.

## Out of scope
- The Notify sample (34.3).
- Any other `TypeModel` member.
