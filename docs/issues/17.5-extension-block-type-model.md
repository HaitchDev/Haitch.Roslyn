# 17.5 Extension blocks in TypeModel

## Goal
`TypeModel.From` on an extension block throws `ArgumentException` naming the block, and modelling a class that declares extension blocks (including an extension indexer) succeeds without them.

## Touches
- `src/Haitch.Roslyn/Models/TypeModel.cs`
- `tests/Haitch.Roslyn.CSharp15.Tests/ExtensionBlockTests.cs` (new)

## Acceptance
`dotnet test` from the repo root passes, including `ExtensionBlockTests`: the exception and message for an extension block symbol; `TypeModel.From(includeMembers: true)` on the containing static class lists its ordinary static methods and no extension-block members or nested types.

## Constraints
- Detect the block without referencing `TypeKind.Extension` (4.12 lacks it): e.g. the declaring syntax's `Keyword.ValueText == "extension"` or a `TypeKind` value outside the known range. Pick one and say why in a comment.

## Out of scope
- Modelling extension members.
