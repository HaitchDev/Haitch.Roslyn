# 6.4 Caching hazard walker

## Goal
`AssertCacheable` throws `GeneratorTestException` naming the step and member path when a named step's output holds a caching hazard.

## Touches
- `src/Haitch.Roslyn.Testing/CachingHazardWalker.cs` (new)
- `src/Haitch.Roslyn.Testing/GeneratorHarness.cs`
- `tests/Haitch.Roslyn.Tests/Testing/CachingHazardWalkerTests.cs` (new)

## Acceptance
`dotnet test` from the repo root passes, including `CachingHazardWalkerTests`: one test per hazard kind (`ISymbol`, `SyntaxNode`, `Compilation`, `ImmutableArray<T>`, `T[]`, a class without value equality) asserts the message contains a path such as `Item1.Members[0].Symbol`; a model built from this repo's `TypeModel`, `SyntaxInfo` and `EquatableArray<AttributeModel>` reports nothing.

## Out of scope
- Caller-configurable hazard rules or allowlists (follow-up if needed).
- Notes: prerequisites: 6.3. Walk public and private instance fields (record and auto-property backing fields included), recursing into structs (tuples included) and value-equal classes; track visited references to stop on cycles. Also hazards: `SemanticModel`, `SyntaxTree`, `Location`. Safe leaves: primitives, `string`, enums, `DiagnosticDescriptor` (value-equal, held by `DiagnosticInfo`), `LocalizableString`. A class is reference-equal if it does not override `Equals(object)`. Any generic type whose definition name is `EquatableArray`1` (the source-only type is `internal` in each consumer, so match by name) is walked element by element and its backing array is not a hazard. Also expose `CachingHazardWalker.Find(object? value)` returning the hazard path or null, so callers can check a model directly.
