# 17.3 Unions in TypeModel

## Goal
`TypeModel.From` and `ContainingTypeModel` record a union's kind and case types, and partial declarations of a union (as target or containing type) are written as `partial union`, so generated parts compile.

## Touches
- `src/Haitch.Roslyn/Models/TypeModel.cs`
- `src/Haitch.Roslyn/Models/ContainingTypeModel.cs`
- `src/Haitch.Roslyn/Writing/SourceWriterExtensions.cs`
- `tests/Haitch.Roslyn.CSharp15.Tests/UnionModelTests.cs` (new)

## Acceptance
`dotnet test` from the repo root passes, including `UnionModelTests`: kind is `Union` and case types are `Cat`,`Dog` (in order) for `public partial union Pet(Cat, Dog);`; a generated partial part adding a method compiles with zero diagnostics (today: CS0261, `partial struct`); same for a union containing a nested partial class; a hand-written `partial struct` implementing `IUnion` stays `Struct` and its generated part compiles.

## Constraints
- Detection (revised after review): source types are unions when a declaring syntax's keyword is `union`; metadata types when they carry `System.Runtime.CompilerServices.UnionAttribute`. Implementing `IUnion` alone is not enough (a hand-written struct must stay `partial struct`). Case types: parameter types of the implicitly declared one-parameter instance constructors, in declaration order, as `TypeRef`s, only when the kind is `Union`. Do not compare `TypeKind` against values 4.12 lacks.
- Add `Union` to the existing type-declaration kind enum; new model data is `init` properties (`UnionCaseTypes` as `EquatableArray<TypeRef>`, empty for non-unions).
- Non-union output stays byte-identical.
- TDD: show the partial-part compile test failing with CS0261 before the fix. Edit only with Rider MCP tools.
