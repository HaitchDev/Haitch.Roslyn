# 20.1 CancellationToken on model factories

## Goal
`TypeModel.From` and `MethodModel.From` take an optional `CancellationToken`, check it per member, and `ForTypesWithAttribute` passes its token through.

## Touches
- `src/Haitch.Roslyn/Models/TypeModel.cs`
- `src/Haitch.Roslyn/Models/MethodModel.cs`
- `src/Haitch.Roslyn/Generators/SyntaxValueProviderExtensions.cs`
- `tests/Haitch.Roslyn.Tests/Models/TypeModelTests.cs`

## Acceptance
`dotnet test` from the repo root passes, including tests that `TypeModel.From(symbol, includeMembers: true, cancelled)` and `MethodModel.From(symbol, cancelled)` throw `OperationCanceledException`, and that an uncancelled token produces a model equal to the token-less call.

## Constraints
- The token is the last parameter, defaulted, so existing calls compile unchanged. Method-group uses inside `TypeModel.From` become lambdas.
- TDD: behavioural red first (CS1501 alone is not enough; show a cancelled token being ignored by a stub). Edit only with Rider MCP tools.

## Out of scope
- Tokens on `PropertyModel`, `FieldModel`, `TypeParameterModel` (they don't loop).
