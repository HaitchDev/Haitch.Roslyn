# 7.1 HintName.For

## Goal
`HintName.For(TypeModel, suffix)` returns a per-type unique hint name that `AddSource` accepts for every type shape (namespaced, global, nested, generic).

## Touches
- `src/Haitch.Roslyn/Generators/HintName.cs` (new)
- `tests/Haitch.Roslyn.Tests/Generators/HintNameTests.cs` (new)

## Acceptance
`dotnet test` from the repo root passes, including `HintNameTests`: expected strings for each shape, distinct names for `Foo` and `Foo<T>` and for `A.B` (namespace) vs `A+B` (nested), an invalid suffix throws `ArgumentException`, and a test generator that calls `AddSource` with every produced name runs without an exception.

## Out of scope
- Deduping (7.2), wiring into a sample generator (8.2).
- Notes: prerequisites: none. Format: `{Namespace.}{Outer.}*{Name}{`N if generic}.{suffix}.g.cs`, e.g. ``My.App.Outer.Inner`1.Equality.g.cs``, global namespace has no prefix; containing types contribute their own arity too. If `AddSource` rejects the backtick, use `_N` instead and say so in the report. Nested types use `.` like namespaces, so state the uniqueness rule that distinguishes them (e.g. `+` for nesting if `AddSource` accepts it) and test it. The suffix is required, non-empty, must not end in `.cs`, and may only contain characters `AddSource` allows (letters, digits, `.`, `_`, `-`); validate it in `For`, not only in Roslyn. `internal static class`, file header rules apply.
