# 0.3 Package smoke test

## Goal
A test packs the package to a temporary feed and builds a `netstandard2.0` consumer project that uses it, failing if the consumer does not compile.

## Touches
- `tests/Haitch.Roslyn.Tests/PackageSmokeTests.cs` (new)
- `tests/PackageSmoke/Consumer/Consumer.csproj` (new, not in the solution)
- `tests/PackageSmoke/Consumer/Usage.cs` (new; uses `EquatableArray<T>`)
- `tests/Haitch.Roslyn.Tests/Haitch.Roslyn.Tests.csproj` (only to exclude/copy the consumer folder)

## Acceptance
Rider test run of `PackageSmokeTests` passes; temporarily breaking the pack (e.g. removing the `contentFiles` item) makes it fail.

## Out of scope
- Adding the consumer to the solution.
- A generator in the consumer; compiling the sources is enough.
- Notes: the consumer must restore from the temp feed only (its own `nuget.config` generated by the test) with a unique package version per run so the NuGet cache does not mask changes; it must have warnings as errors. Run it twice: nullable enabled, and nullable disabled, to prove the file headers work. The consumer sets `LangVersion` 14, since consumers need C# 14 (Polyfill 11.4.0's own sources use C# 14 `extension` blocks), so anything newer in shipped code still fails the test.
