# 14.1 EquatableArray is a read-only list

## Goal
`EquatableArray<T>` implements `IReadOnlyList<T>`, so LINQ and `IEnumerable<T>` consumers accept it directly.

## Touches
- `src/Haitch.Roslyn/Types/EquatableArray.cs`
- `tests/Haitch.Roslyn.Tests/Types/EquatableArrayAccessTests.cs`

## Acceptance
`dotnet test` from the repo root passes the full suite, including new tests that pass an `EquatableArray<int>` (populated and `default`) to a method taking `IReadOnlyList<int>` and to LINQ `Select`/`Count()`, asserting the full sequence, and a test that `default` enumerates as empty through `IEnumerable<int>` without throwing.

## Constraints
- Interface members are explicit implementations; the public struct `Enumerator` and `GetEnumerator()` stay, so `foreach` stays allocation-free.
- Equality, hash code and `default` handling are unchanged; `EquatableArrayTests` pass unchanged.
- `CachingHazardWalker` still walks `EquatableArray`1` element by element (it matches by name first); the hazard tests pass unchanged.
- If TUnit now resolves `Assert.That(equatableArray)` to a collection assertion and an existing test changes meaning, fix the test minimally and list each one in the report.
- Prove the netstandard2.0 build: Rider builds the solution with zero warnings, and `PackageSmokeTests` passes.
- TDD: show the `IReadOnlyList<int>` test failing (CS1503) before the change.
- Edit only with Rider MCP tools; never write files via Bash.

## Out of scope
- Collection expressions (14.2), `ICollection<T>`/`IList<T>`, any mutation API.
- Notes: prerequisites 1.1 and 1.2. Raised in the handoff.
