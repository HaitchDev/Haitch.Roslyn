# 39.22 GeneratorHarness runs analyzers over the generated compilation

## Goal
`GeneratorHarness.Run(IIncrementalGenerator generator, GeneratorHarnessInput input, ImmutableArray<DiagnosticAnalyzer> analyzers)` runs the given analyzers over the compilation that includes the generated sources and exposes what they report as `GeneratorHarnessResult.AnalyzerDiagnostics`, leaving out what `#pragma warning disable`, `[SuppressMessage]` or the input's analyzer config options (`dotnet_diagnostic.<id>.severity = none`) suppress, as a real build would.

## Touches
- `src/Haitch.Roslyn.Testing/GeneratorHarness.cs`
- `src/Haitch.Roslyn.Testing/GeneratorHarnessResult.cs`
- the `GeneratorHarness` test file(s) under `tests/Haitch.Roslyn.Tests` (a new test file beside them for the analyzer cases, and a small test-only analyzer in it, is fine)

## Acceptance
`.claude/check.sh` exits 0.

## Constraints
- Found by Haitch.Validation item 3 (2026-10-12): its generator's two warnings (HV0016, HV0017) move into a `DiagnosticAnalyzer` shipped in the generator assembly, so `#pragma`, `[SuppressMessage]` and `.editorconfig` severity work (Roslyn's guidance: warnings from analyzers). Its generator tests need to run the generator and the analyzer together on one input and assert the analyzer's diagnostics at source locations. A probe (Roslyn 4.12, `CompilationWithAnalyzers` on the generated compilation with the input's `AnalyzerConfigOptionsProvider`) showed pragma and `[SuppressMessage]` suppression excluded by default and editorconfig `none` honoured.
- `AnalyzerDiagnostics` is empty (not default) when `Run` is called without analyzers; the existing overloads keep their behaviour and signatures. Analyzer exceptions surface as a test failure (`GeneratorTestException` or the harness's existing failure idiom), not a silent empty result.
- Tests: (1) a test-only analyzer reporting a warning on every class declaration is reported at the class's span; (2) `#pragma warning disable <id>` around the class leaves it out; (3) `[SuppressMessage]` leaves it out; (4) an input analyzer config `dotnet_diagnostic.<id>.severity = none` leaves it out (use the input's existing config-options support; if the input cannot carry editorconfig-style options, stop and report); (5) the analyzer sees generated sources (a diagnostic in a generated file is reported); (6) no analyzers -> empty.
