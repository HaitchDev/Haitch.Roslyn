# 23.4 Diagnostic assertions

## Goal
`GeneratorHarnessResult` offers `AssertNoDiagnostics()` and `AssertDiagnostic(id, …)`, which throw `GeneratorTestException` with a readable list of actual diagnostics on mismatch.

## Touches
- `src/Haitch.Roslyn.Testing/GeneratorHarnessResultAssertions.cs` (new, public static extension class)
- `tests/Haitch.Roslyn.Tests/Testing/DiagnosticAssertionTests.cs` (new)

## Acceptance
`.claude/check.sh` exits 0, including passing and failing cases for: no diagnostics; a matching id; wrong id; wrong severity; wrong line/column; message substring missing; two diagnostics when one is asserted.

## Constraints
- `AssertDiagnostic(string id, DiagnosticSeverity? severity = null, int? line = null, int? column = null, string? file = null, string? messageContains = null)` asserts exactly one generator diagnostic with that id matches and returns it. Line and column are 1-based.
- `AssertNoDiagnostics()` covers generator diagnostics only.
- Failure messages list every actual diagnostic as `id severity file(line,col): message`.
- Returns `this`-style values where useful for chaining; no test-framework dependency.
- TDD: behavioural red first. Edit only with Rider MCP tools.

## Out of scope
- Asserting on input or output-compilation diagnostics, expected-output assertions.
