# 18.1 Open-block depth

## Goal
`SourceWriter` tracks open-block depth; a `BodyScope` throws `InvalidOperationException` when written to while one of its child scopes is still open, and its `Dispose` never throws: it closes any blocks still open inside it, then its own, and a copy disposed after the original is a no-op.

## Touches
- `src/Haitch.Roslyn/Writing/SourceWriter.cs`
- `src/Haitch.Roslyn/Writing/Scopes/BodyScope.cs`
- `tests/Haitch.Roslyn.Tests/Writing/Scopes/ScopeGuardTests.cs` (new)
- `tests/Haitch.Roslyn.Tests/Writing/Scopes/MethodScopeTests.cs` (two tests wrote through the parent while a `Block` child was open; write through the child instead)

## Acceptance
`dotnet test` from the repo root passes the full suite (existing expected outputs unchanged), including `ScopeGuardTests`: `Line` on an outer body while a nested `If`/`ForEach`/`Block` is open throws; disposing a copied `BodyScope` after the original writes nothing more; disposing a parent with a child left open closes both blocks (balanced braces) without throwing; normal nesting produces identical output.

## Constraints
- Depth is the writer's existing indent level (internal getter); each scope records the depth of its own block at open and checks `writer depth == own depth` before writing.
- Round rule (applies to all of slice 18): `Dispose` never throws, because a throw there replaces an exception already in flight. Problems only detectable at dispose (18.4–18.6) are recorded on the writer and thrown from `ToString()`/`ToSourceText()`.
- Messages name the scope type and say what is still open.
- Guards always run (no `#if DEBUG`).
- TDD: behavioural red first (today the misuse silently misnests). Edit only with Rider MCP tools.

## Out of scope
- Chaining methods (18.2), declaration scopes (18.3).
