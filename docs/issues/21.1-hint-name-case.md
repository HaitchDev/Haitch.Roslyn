# 21.1 Hint-name case disambiguation

## Goal
`HintName.For` has an opt-in mode that appends a short stable hash of the case-sensitive type name, so types differing only in case get distinct hint names; the default output is unchanged.

## Touches
- `src/Haitch.Roslyn/Generators/HintName.cs`
- `tests/Haitch.Roslyn.Tests/Generators/HintNameTests.cs`

## Acceptance
`dotnet test` from the repo root passes, including tests that `Foo` and `foo` in one namespace get hint names that differ case-insensitively in opt-in mode, that the hash is identical across runs (a pinned expected value), that the default mode output matches today's for every existing test, and that a generator adding both via `AddSource` produces two files.

## Constraints
- Hash: FNV-1a 32-bit over the UTF-16 code units of the full case-sensitive name (namespace, containing types, arity), as 8 lowercase hex chars, placed before the suffix: `Ns.Foo.a1b2c3d4.Suffix.g.cs`. No `System.HashCode` (netstandard2.0) and no `string.GetHashCode` (randomised).
- Opt-in shape: a new optional `bool disambiguateCase = false` parameter. Update the doc comment that says case is not disambiguated.
- TDD: behavioural red first. Edit only with Rider MCP tools.

## Out of scope
- Changing default hint names.
