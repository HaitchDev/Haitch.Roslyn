# 6.1 Testing project scaffold

## Goal
The test project references a packable `src/Haitch.Roslyn.Testing` project in the solution.

## Touches
- `src/Haitch.Roslyn.Testing/Haitch.Roslyn.Testing.csproj` (new)
- `src/Haitch.Roslyn.Testing/GeneratorTestException.cs` (new)
- `Haitch.Roslyn.slnx` (add the project under `/src/`)
- `tests/Haitch.Roslyn.Tests/Haitch.Roslyn.Tests.csproj` (add the `ProjectReference` only)
- `tests/Haitch.Roslyn.Tests/Testing/GeneratorTestExceptionTests.cs` (new)

## Acceptance
`dotnet pack src/Haitch.Roslyn.Testing -c Release -o "$TMPDIR/haitch-testing-pack" && dotnet test` from the repo root succeeds, and the pack output contains `Haitch.Roslyn.Testing.*.nupkg`; `GeneratorTestExceptionTests` passes.

## Out of scope
- The harness itself (6.2), package metadata, icon, README, SourceLink (9.2), central package management (9.1).
- Notes: prerequisites: none. This is a normal package, not source-only: `net10.0`, public types, ships its DLL, no `// <auto-generated/>` header rule (that rule and `SourceHeaderTests` cover `src/Haitch.Roslyn` only). It references `Microsoft.CodeAnalysis.CSharp` 4.8.0 as a real (flowing) dependency, as spec-next.md names, and does not reference Haitch.Roslyn. The test project's `src/Haitch.Roslyn/**` compile glob must not pick up the new sibling folder; check it does not.
