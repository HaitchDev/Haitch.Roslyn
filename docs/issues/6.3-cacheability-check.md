# 6.3 Cacheability check

## Goal
`GeneratorHarness.AssertCacheable` reruns a generator on a cloned compilation plus a trivia-only edit and throws `GeneratorTestException` naming the first tracked step whose outputs are not all `Cached` or `Unchanged`.

## Touches
- `src/Haitch.Roslyn.Testing/GeneratorHarness.cs`
- `tests/Haitch.Roslyn.Tests/Testing/CacheabilityTests.cs` (new)

## Acceptance
`dotnet test` from the repo root passes, including `CacheabilityTests`: a fixture generator with value-equal models passes, one whose step carries a fresh `object` per run fails with a message containing the step name, output index and reason, and an unknown step name fails with a message listing the step names that exist.

## Out of scope
- Inspecting step output types for hazards (6.4).
- Migrating this repo's existing caching tests (6.5).
- Notes: prerequisites: 6.2. Suggested shape: `AssertCacheable(IIncrementalGenerator generator, IEnumerable<string> sources, params string[] trackedStepNames)` returning the first run's `GeneratorHarnessResult`. Two reruns from the first run's driver: (1) `compilation.Clone()`, (2) the first syntax tree with trivia appended at the end of the file (a comment plus newline), so no `LocationInfo` above it shifts. Assert per named step via `GetRunResult().Results[0].TrackedSteps[name]`, every `Outputs[i].Reason`. A named step that never ran is a failure, not a pass (typo protection).
