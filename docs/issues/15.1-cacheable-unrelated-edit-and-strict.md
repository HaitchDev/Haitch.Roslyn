# 15.1 AssertCacheable unrelated-file edit and strict mode

## Goal
`GeneratorHarness.AssertCacheable` accepts a `CacheabilityOptions` that adds an unrelated edit to a named later source and can require recomputation after the trivia edit.

## Touches
- `src/Haitch.Roslyn.Testing/CacheabilityOptions.cs` (new, `public sealed class` with init properties `int? UnrelatedEditSourceIndex` and `bool RequireRecomputationAfterTriviaEdit`)
- `src/Haitch.Roslyn.Testing/GeneratorHarness.cs`
- `tests/Haitch.Roslyn.Tests/Testing/CacheabilityTests.cs`
- `README.md` (one line in the Testing section naming the options)

## Acceptance
`dotnet test` from the repo root passes the full suite, including new `CacheabilityTests`: the unrelated edit passes for a value-equal generator and fails, with the full exception message asserted, for a generator whose model captures the compilation's type count; strict mode passes for a single-source per-item step and fails with the full message when the output is `Cached`; an out-of-range or zero `UnrelatedEditSourceIndex` throws `GeneratorTestException` with the full message asserted.

## Constraints
- Add an overload `AssertCacheable(generator, sources, trackedStepNames, CacheabilityOptions options, additionalReferences = null, parseOptions = null)`; existing overloads delegate to it with default options and behave exactly as before.
- Run 3 (unrelated edit) runs after run 2 and replaces source `UnrelatedEditSourceIndex` with its text plus an empty `namespace HarnessUnrelatedEdit { }` on its own line; it requires `Cached` or `Unchanged` and names the scenario "an unrelated edit in Source{n}.cs" in failures. Index 0 is rejected because run 2 already edits it.
- `RequireRecomputationAfterTriviaEdit` applies to run 2 only: besides every output being `Cached` or `Unchanged`, at least one output of each named step must be `Unchanged` (the step re-ran and produced an equal value); the failure message names the step and run.
- XML docs on every new public member; the harness stays in the Testing package's public API style.
- TDD: show each new failure-path test failing before the code.
- Edit only with Rider MCP tools; never write files via Bash.
