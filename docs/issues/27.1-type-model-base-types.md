# 27.1 TypeModel base types and interfaces

## Goal
`TypeModel.From` records the type's base class, its directly declared interfaces and all its interfaces as equatable `TypeRef`s.

## Touches
- `src/Haitch.Roslyn/Models/TypeModel.cs`
- `tests/Haitch.Roslyn.Tests/Models/TypeModelTests.cs`

## Acceptance
`.claude/check.sh` exits 0, including tests for: a class with a user base class; a class with no explicit base (`BaseType` is null); a struct, enum, record and interface; direct versus inherited interfaces (an interface from a base class appears in `AllInterfaces` only); generic interfaces such as `IEquatable<T>`; and two `From` calls on the same symbol giving equal models.

## Constraints
- New `init` properties: `TypeRef? BaseType`, `EquatableArray<TypeRef> Interfaces` (declared directly, `INamedTypeSymbol.Interfaces`) and `EquatableArray<TypeRef> AllInterfaces`. The positional constructor is unchanged.
- `BaseType` is null for `object`, `System.ValueType`, `System.Enum`, interfaces and any type with no base.
- Populated whether or not `includeMembers` is set (cheap, and needed for discovery decisions). Order follows Roslyn's order.
- Build `TypeRef`s the way existing members build them; no symbols in the model.
- TDD: behavioural red first. Edit only with Rider MCP tools.

## Out of scope
- `ContainingTypeModel` base types, writing base lists (27.4), events (27.2).
