# 26.2 Additional-file provider

## Goal
`ForAdditionalFiles` yields an equatable `AdditionalFileModel` per matching additional file, or a `Result` failure when its text cannot be read.

## Touches
- `src/Haitch.Roslyn/Generators/AdditionalFileExtensions.cs` (new)
- `src/Haitch.Roslyn/Models/AdditionalFileModel.cs` (new)
- `tests/Haitch.Roslyn.Tests/Generators/AdditionalFileTests.cs` (new)

## Acceptance
`.claude/check.sh` exits 0, including (via `GeneratorHarnessInput.AdditionalTexts` and `PerFileOptions`): files filtered by path predicate; content and path round-trip; requested `build_metadata.AdditionalFiles.<Name>` values present, missing ones null; an unreadable text yields a failure carrying the caller's descriptor and the path; `AssertCacheable` passes on an unrelated source edit.

## Constraints
- Extension on `IncrementalGeneratorInitializationContext`: `ForAdditionalFiles(Func<string, bool> pathPredicate, DiagnosticDescriptor unreadable, params string[] metadataNames)` returning `IncrementalValuesProvider<Result<AdditionalFileModel>>`.
- The path predicate runs before the text is read. Text is read with the cancellation token.
- `AdditionalFileModel(string Path, string Content, EquatableArray<…> Metadata)` with a `TryGetMetadata(name, out string?)`; empty metadata values are null.
- If combining with `AnalyzerConfigOptionsProvider` breaks caching on unrelated edits, extract the needed values per file before combining; the cacheability test is the judge.
- TDD: behavioural red first. Edit only with Rider MCP tools.

## Out of scope
- Binary files, globbing helpers, editing additional files in cacheability runs.
