# 33.1 Partial events become one EventModel

## Goal
`TypeModel.From(..., includeMembers: true, ...)` on a type with a C# 14 partial event (a defining `partial event EventHandler E;` and an implementing `partial event EventHandler E { add { } remove { } }`) yields exactly one `EventModel` for `E`, with `IsPartial = true` and `IsFieldLike = false`.

## Touches
- `src/Haitch.Roslyn/Models/EventModel.cs`
- `src/Haitch.Roslyn/Models/TypeModel.cs`
- A new test file in `tests/Haitch.Roslyn.CSharp15.Tests/` (for example `PartialEventModelTests.cs`).
- Existing tests or callers the compiler flags if `EventModel`'s shape changes (list them in the report).

## Acceptance
`.claude/check.sh` exits 0, including the new partial-event tests in `tests/Haitch.Roslyn.CSharp15.Tests`.

## Constraints
- First write tests that record what happens today (count of `EventModel`s for `E`, `IsFieldLike`), then the target tests. Show them failing against a stub `IsPartial` that returns `false`.
- Tests cover: the two-part partial event (one model, `IsPartial`, not field-like, attributes from both parts merged the way `PropertyModel` merges partial property attributes, if it does); a static partial event; a non-partial field-like event and a non-partial accessor event (both `IsPartial = false`, unchanged otherwise).
- `src/` compiles against Roslyn 4.12, so do not call `IEventSymbol` members newer than 4.12 (such as `PartialDefinitionPart`). Detect `partial` from declaring syntax modifiers, or another 4.12 API, and explain the choice in one line in the report.
- `IsPartial` is part of value equality. Follow how `PropertyModel.IsPartial` is declared and documented.
- A worker owns every failure in the full suite. Edit only with Rider MCP tools.

## Out of scope
- Writing partial event implementations from the scoped writer.
- An events variant of member discovery (`ForEventsWithAttribute`).
- The Notify sample.
