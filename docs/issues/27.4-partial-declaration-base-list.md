# 27.4 Base list on partial declarations

## Goal
`FileScope.Type`, `NamespaceScope.Type` and `TypeScope.Type` accept extra base types that are written on the innermost partial declaration.

## Touches
- `src/Haitch.Roslyn/Writing/SourceWriterExtensions.cs`
- `src/Haitch.Roslyn/Writing/Scopes/FileScope.cs`
- `src/Haitch.Roslyn/Writing/Scopes/NamespaceScope.cs`
- `src/Haitch.Roslyn/Writing/Scopes/TypeScope.cs`
- `tests/Haitch.Roslyn.Tests/Writing/PartialBaseListTests.cs` (new)

## Acceptance
`.claude/check.sh` exits 0, including tests where generated output compiles for: a top-level partial class gaining `global::System.ComponentModel.INotifyPropertyChanged`; a partial class nested in two partial containing types where only the innermost gains the base list; a generic partial type where the base list precedes the `where` clauses; two base types; and an empty or default list writing exactly what it writes today.

## Constraints
- New optional trailing parameter `EquatableArray<TypeRef> baseTypes = default` on the three `Type(TypeModel)` methods and on `WriteTypeDeclaration`. Every existing call site compiles and renders unchanged.
- Written as ` : A, B` after the name and type parameters, before where clauses, using `FullyQualifiedName`, matching `WriteNewTypeDeclaration`'s base list.
- No validation of base types (the compiler reports conflicts); documented.
- TDD: behavioural red first. Edit only with Rider MCP tools.

## Out of scope
- Base lists on containing types, deriving base types automatically from `TypeModel`.
